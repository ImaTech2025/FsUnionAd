## 2. 添加依赖

### 2.1 引入聚合 SDK 模块

**方式一：源码依赖（推荐开发阶段）**

在 `settings.gradle.kts` 中：
```kotlin
include(":UnionAd")
```

在 app 模块的 `build.gradle.kts` 中：
```kotlin
dependencies {
    implementation(project(":UnionAd"))
}
```

**方式二：AAR 依赖（推荐发布阶段）**

将 `aggregate-ad-sdk-java-1.0.0.aar` 放入 `app/libs/` 目录：
```kotlin
dependencies {
    implementation(fileTree(mapOf("dir" to "libs", "include" to listOf("*.aar"))))
}
```

### 2.2 引入各广告平台 SDK

聚合 SDK 本体采用 `compileOnly` 引用各平台 SDK，**接入方需要在自己的 app 模块中按需引入**：

```kotlin
dependencies {
    // 穿山甲（Pangle）
    implementation("com.pangle.cn:ads-sdk-pro:7.6.1.2")

    // 优量汇（GDT / 腾讯广点通）
    implementation("com.qq.e.union:union:4.560.1470")

    // 百青藤（百度）
    implementation("com.baidu:mobads:9.42.2")

    // 飞梭（Fission）—— 使用本地 AAR
    implementation(fileTree(mapOf("dir" to "libs/fission", "include" to listOf("*.aar"))))
    // 飞梭依赖的三方库
    implementation("androidx.appcompat:appcompat:1.3.1")
    implementation("com.google.guava:guava:31.0.1-android")
    implementation("com.airbnb.android:lottie:5.2.0")
}
```

> **说明**：不需要某平台时，不引入该平台 SDK 即可，SDK 内部会在运行时跳过未引入的平台。

### 2.3 Maven 仓库配置

如需从远端拉取穿山甲、优量汇等 SDK，在 `settings.gradle.kts` 中添加：

```kotlin
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
        // 穿山甲
        maven { url = uri("https://artifact.bytedance.com/repository/pangle") }
        // 优量汇
        maven { url = uri("https://dl-maven-android.tencent.com/repository/maven") }
    }
}
```

## 3. SDK 初始化

在 `Application.onCreate()` 中执行初始化，**必须在任何广告加载之前调用**。

```java
public class MyApplication extends Application {

    @Override
    public void onCreate() {
        super.onCreate();
        // 1. 初始化聚合广告 SDK
        FsUnionSDK.initialize(
            this,
            new FsUnionSDK.Config.Builder()
                .appId("your_aggregate_app_id")   // 聚合平台应用 ID
                .enableLog(BuildConfig.DEBUG)      // Debug 模式开启日志
                .enableMediationReport(true)       // 开启聚合上报
                .reportUrl("https://your.report.server/ad")  // 上报地址（可选）
                .build(),
            success -> {
                if (success) {
                    Log.i("App", "聚合广告 SDK 初始化成功");
                }
            }
        );
    }
}
```

**AndroidManifest.xml 注册 Application：**

```xml
<application
    android:name=".MyApplication"
    ...>
</application>
```

### Config 参数说明

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `appId` | String | — | 聚合平台应用 ID（必填）|
| `enableLog` | boolean | false | 是否输出调试日志 |
| `enableMediationReport` | boolean | true | 是否上报聚合数据 |
| `reportUrl` | String | "" | 数据上报服务地址 |

## 4. 广告策略配置（JSON）

聚合 SDK 采用 **JSON 配置驱动** 的方式管理广告策略。策略类型（`strategyType`）、广告源列表（`sources`）等均在 JSON 中配置，支持以下三种数据来源的自动合并：

### 4.1 JSON 配置结构

```json
{
    "version": 1,
    "strategy": {
        "slotId": "10000001",
        "strategyId": "default",
        "strategies": [
            {
                "type": "BIDDING",
                "priority": 1,
                "timeoutMs": 3000,
                "sources": [
                    {
                        "sdkName": "穿山甲",
                        "sdkType": "PANGLE",
                        "adUnitId": "your_pangle_slot_id",
                        "appid": "your_pangle_app_id",
                        "priority": 1,
                        "bidFloor": 3.0,
                        "timeout": 5000,
                        "enabled": true
                    },
                    {
                        "sdkName": "优量汇",
                        "sdkType": "GDT",
                        "adUnitId": "your_gdt_slot_id",
                        "appid": "your_gdt_app_id",
                        "priority": 2,
                        "bidFloor": 2.0,
                        "timeout": 5000,
                        "enabled": true
                    }
                ]
            }
        ]
    }
}
```

> **结构说明**（schema v2）：
> - 顶层 `strategy` 是**单条** `AdUnitConfig`（不再以 slotId 为 key 索引 Map），其内部 `slotId` 与请求参数 `AdRequestParams.slotId` **强制一致校验**，不一致时拒绝执行并 `onNoFill`。
> - 单阶段 vs 链式：单条广告位下 `strategies` 数组长度为 1 时走单阶段（按 `type` 路由到 `BiddingStrategy` / `WaterfallStrategy`）；长度 ≥ 2 时走 `HybridStrategy` 优先级链。
> - 每个广告源在 `sources` 中独立配置 `appid` / `adUnitId` / `token`，无需顶层 `platformAppIds`。

### 4.2 AdUnitConfig JSON 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `slotId` | String | ✅ | 广告位 ID（8 位数字），必须与 `AdRequestParams.slotId` 完全一致 |
| `strategyId` | String | ❌ | 策略 ID，用于追踪一次广告请求所采用的策略来源（本地默认 `default`，云端可下发） |
| `adFormat` | String | ✅ | 广告格式：`SPLASH` / `INTERSTITIAL` / `REWARDED_VIDEO` / `FEED_TEMPLATE` / `FEED_RENDER` |
| `strategyType` | String | ✅ | 竞价策略：`WATERFALL` / `BIDDING` / `HYBRID` |
| `timeoutMs` | long | ❌ | 整个策略执行的最大超时时间（ms），包含平台 SDK 初始化时间 + 各广告源请求召回时间。默认 3000ms |
| `refreshInterval` | long | ❌ | 信息流刷新间隔（ms），默认 0 |
| `sources` | Array | ✅ | 广告源配置列表 |

### 4.3 AdSourceConfig JSON 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sdkName` | String | ✅ | 当前广告源的全局别名，用于统一识别统计|
| `sdkType` | String | ✅ | 平台类型：`PANGLE` / `GDT` / `BAIDU` / `FISSION` / `CUSTOM` |
| `adFormat` | String | ✅ | 广告格式（与 adUnit 一致）|
| `adUnitId` | String | ✅ | 平台侧广告位 ID |
| `appId` | String | ✅ | 平台侧 App ID |
| `ecpm` | double | ❌ | 预估 CPM（单位：分），瀑布流排序用，默认 0 |
| `priority` | int | ❌ | 优先级（数字越小越优先），默认 0 |
| `bidFloor` | double | ❌ | Bidding 最低接受价格（单位：分），默认 0 |
| `timeout` | long | ❌ | 单次请求超时（ms），默认 5000ms |
| `enabled` | boolean | ❌ | 是否启用该广告源，默认 true |
| `adapterClassName` | String | ❌ | **仅自定义 ADN**：Adapter 全路径类名。聚合 SDK 首次解析该广告源时通过反射创建适配器实例。内置平台（PANGLE/GDT/BAIDU/FISSION）不需要此字段 |

> **注意**：`AdSourceConfig` 不再持有 `strategyId` 字段，策略 ID 只能在 `AdUnitConfig`（unit）级别配置。如需在源码级别引用，请通过所属 `AdUnitConfig.strategyId` 获取。

### 4.4 策略类型说明

| 策略 | 说明 | 适用场景 |
|---|---|---|
| `WATERFALL` | 按 priority 升序、ecpm 降序逐一请求 | 填充率优先 |
| `BIDDING` | 并发向所有源发起竞价，取最高价者 | 收益最大化 |
| `HYBRID` | 多阶段 priority chain：前一阶段 noFill 后推进到下一阶段 | **推荐默认使用** |

> 💡 **建议**：在 `assets/ad_strategy_*.json` 中维护默认配置，也可从服务端拉取后传入。

### 4.5 slotId 校验

`AdStrategyManager.execute()` 入口处强制校验 `params.slotId == unitConfig.slotId`：
- 二者任一为空 → 立即 `onNoFill("slotId mismatch: request=null config=...")`
- 二者不一致 → 立即 `onNoFill("slotId mismatch: request=A config=B")`，不进入策略执行

云端拉取的配置也会做同样校验（`CloudStrategyManager.parseDefaultStrategyJson` / `fetchFromCloud`），避免用错位配置拉取广告导致三方 SDK 报错。

## 5. 开屏广告

```java
public class SplashActivity extends AppCompatActivity {

    private FsSplashAdManager splashManager;
    private IFsUnionSplashAd splashAd;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);

        // 1. 创建管理器（只需 Context）
        splashManager = FsUnionSDK.createSplashAdManager(this)
            .setListener(new FsUnionSplashAdListener() {
                @Override
                public void onAdShow(IFsUnionSplashAd ad) {
                    // 广告加载成功，保存广告对象并展示
                    splashAd = ad;
                    splashAd.setListener(this);
                    splashAd.show(splashContainer);
                }

                @Override
                public void onAdClose(IFsUnionSplashAd ad) {
                    // 广告关闭（播放完毕或用户手动关闭），跳转主页
                    navigateToMain();
                }

                @Override
                public void onSplashAdSkipped(IFsUnionSplashAd ad) {
                    // 用户点击跳过
                    navigateToMain();
                }

                @Override
                public void onAdError(IFsUnionSplashAd ad, int errorCode, String errorMsg) {
                    // 广告加载失败，直接跳转主页
                    Log.e("Splash", "Error[" + errorCode + "]: " + errorMsg);
                    navigateToMain();
                }
            });

        // 2. 加载广告（传入 slotId + 默认策略 JSON）
        String splashStrategyJson = loadJsonFromAssets("ad_strategy_splash.json");
        splashManager.load(new AdRequestParams.Builder()
                .slotId("10000001")
                .defaultStrategyJson(splashStrategyJson)
                .build());
    }

    private void navigateToMain() {
        startActivity(new Intent(this, MainActivity.class));
        finish();
    }

    @Override
    protected void onDestroy() {
        super.onDestroy();
        if (splashManager != null) splashManager.destroy();
    }
}
```

### IFsUnionSplashAd 回调说明

| 回调 | 触发时机 |
|---|---|
| `onAdShow(ad)` | 广告展示曝光 |
| `onSplashAdSkipped(ad)` | 用户点击跳过按钮 |
| `onAdClick(ad)` | 用户点击广告 |
| `onAdClose(ad)` | 广告关闭（播放完毕或用户手动关闭） |
| `onAdError(ad, code, msg)` | 加载或展示失败 |

#### SDK 回调支持矩阵

| 回调 | 穿山甲 | 优量汇 | 百青藤 | 飞梭 |
|---|:---:|:---:|:---:|:---:|
| `onAdShow` | ✅ | ✅ | ✅ | ✅ |
| `onAdClick` | ✅ | ✅ | ✅ | ✅ |
| `onAdClose` | ✅ | ✅ | ✅ | ✅ |
| `onSplashAdSkipped` | ✅ | ❌ | ✅ | ✅ |
| `onAdError` | ✅ | ✅ | ✅ | ✅ |

> **注意**：优量汇 SDK 不提供开屏跳过回调，`onSplashAdSkipped` 不会被触发。穿山甲通过 `onSplashAdClose` 的 `type` 参数区分跳过（`CLICK_SKIP`）和正常关闭。

### 广告对象信息

```java
splashAd.getEcpm();       // 获取该广告的 eCPM 价格
splashAd.getSdkType();    // 获取该广告的 SDK 类型（如 AdSdkType.PANGLE）
splashAd.getSdkName();   // 获取该广告的 SDK 名称
splashAd.getSlotId();     // 获取该广告位 ID

// ⚠️ 展示前务必检查广告就绪状态！
if (splashAd.isReady()) {
    splashAd.show(splashContainer);
} else {
    // 广告已失效（素材过期等），放弃展示或重新加载
    navigateToMain();
}
```

> ⚠️ **重要**：`isReady()` 是实时检查（非快照值）。广告加载成功后素材可能因缓存失效/过期而变化，
> **务必在调用 `show()` 前调用 `isReady()` 做二次确认**，否则可能展示空白或已过期的广告。

## 6. 插屏广告

```java
public class GameActivity extends AppCompatActivity {

    private FsInterstitialAdManager interstitialManager;
    private IFsUnionInterstitialAd interstitialAd;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);

        // 1. 创建管理器
        interstitialManager = FsUnionSDK.createInterstitialAdManager(this)
            .setListener(new FsUnionInterstitialAdListener() {
                @Override
                public void onAdShow(IFsUnionInterstitialAd ad) {
                    interstitialAd = ad;
                    Log.d("Interstitial", "已加载，来源: " + ad.getSdkName()
                            + " ecpm=" + ad.getEcpm());
                }
                @Override
                public void onAdClose(IFsUnionInterstitialAd ad) {
                    interstitialAd = null;
                    // 广告关闭后预加载下一条
                    interstitialManager.load(new AdRequestParams.Builder()
                            .slotId("10000002")
                            .defaultStrategyJson(defaultStrategyJson)
                            .build());
                }
                @Override
                public void onAdError(IFsUnionInterstitialAd ad, int errorCode, String errorMsg) {
                    interstitialAd = null;
                    Log.e("Interstitial", "Error[" + errorCode + "]: " + errorMsg);
                }
            });

        // 2. 预加载
        interstitialManager.load(new AdRequestParams.Builder()
                .slotId("10000002")
                .defaultStrategyJson(defaultStrategyJson)
                .build());
    }

    // 在合适时机展示，例如关卡结束
    public void onLevelComplete() {
        if (interstitialAd != null) {
            interstitialAd.show();
        }
    }

    @Override
    protected void onDestroy() {
        super.onDestroy();
        if (interstitialManager != null) interstitialManager.destroy();
    }
}
```

```java
        // 发放奖励给用户
```

## 10. 配置选择优先级

SDK 在每次 `load()` 时自动选择配置，优先级从高到低：

```
┌─────────────────────────────────────────────┐
│  Layer 1: 本地缓存 / 云端配置                   │  ← 优先级最高
│  CloudStrategyManager 从 HTTP 拉取并缓存         │
├─────────────────────────────────────────────┤
│  Layer 2: defaultStrategyJson（默认策略）      │  ← load() 时传入
│  assets JSON 或本地默认配置                     │
└─────────────────────────────────────────────┘
```

### 10.1 选择规则

- **云端优先**：如果本地缓存/云端有该 slotId 的配置，直接使用云端配置
- **默认兜底**：云端无配置时，使用 `defaultStrategyJson` 解析出的配置
- **仅 slotId**：如果连默认策略 JSON 也未传入，则返回 null（广告加载会失败）

### 10.2 使用示例

```java
// 方式一：传入 slotId + 默认策略 JSON
manager.load(new AdRequestParams.Builder()
        .slotId("10000001")
        .defaultStrategyJson(defaultStrategyJson)
        .build());

// 方式二：仅传入 slotId（完全依赖云端/本地缓存配置）
manager.load(new AdRequestParams.Builder()
        .slotId("10000001")
        .build());
```

### 10.3 策略选择建议

| 广告格式 | 推荐策略 | 说明 |
|---|---|---|
| 开屏 | HYBRID | 对填充率要求高，需要瀑布流兜底 |
| 插屏 | WATERFALL / HYBRID | 场景频率高，稳定优先 |
| 激励视频 | BIDDING / HYBRID | 高价值广告，追求收益 |
| 信息流 | HYBRID | 追求收益同时保证填充 |

## 11. 自定义广告平台接入

### 11.1 概述

聚合 SDK 提供了一套标准化的自定义 ADN（Ad Network）接入框架，接入方可按广告格式继承对应的抽象类，实现自己的广告平台适配器。

**核心设计原则：**

| 原则 | 说明 |
|---|---|
| **Adapter 全局单例** | 每个 Adapter 在 SDK 初始化时注册一次，全局复用。适配器本身上不保存任何跨请求状态。 |
| **FsUnionListenerBridge 桥接** | 当三方 SDK 的回调必须在广告对象构造时注册，而业务监听器在 show/render 阶段才可用时，通过 Bridge 将请求阶段和展示阶段的监听器连接起来。 |
| **per-request 状态隔离** | 广告对象、ecpm 等信息存入 `UnionAdResponse`，展示监听器存入 `FsUnionListenerBridge`（挂在 `response.extra` 上），不同请求互不干扰。 |
| **禁止成员变量存状态** | Adapter 上**禁止**添加 `private XxxListener mShowListener` 等成员字段。所有 per-request 状态必须通过 `UnionAdResponse.extra` / `FsUnionListenerBridge` 传递。 |

**接入总览：**

```
后台 JSON 配置 adapterClassName
        │
        ▼
AdSourceConfig.fromJson() 解析 adapterClassName
        │
        ▼
StrategyUtils.resolveAdapter()
   ├── registry.getAdapter() → miss
   └── AdapterFactory.createIfAbsent() → Class.forName() → new → register
        │
        ▼
   adapter.request(context, params, sourceConfig, callback)
        │
        ▼
   adapter.showXxx(response, listener)
```

---

### 11.2 Adapter 架构设计（单例 + Bridge）

**为什么是单例 Adapter？**

聚合 SDK 中每个 Adapter 是**全局单例**——`FsUnionSDK.init()` 时注册一次，之后所有广告请求复用同一个实例。这和聚合 SDK 内部的初始化语义完全匹配（三方 SDK 也是全局初始化一次）。

**单例又如何保证并发安全？**

关键在于 **Adapter 上不保存任何跨请求状态**。广告对象存在 `UnionAdResponse.nativeAd` 中，展示监听器存在 `FsUnionListenerBridge`（挂在 `response.extra` 上），每个请求有自己独立的 response/bridge 实例：

```
请求 A: responseA.extra → BridgeA → listenerA
请求 B: responseB.extra → BridgeB → listenerB   ← 互不干扰
Adapter: (无状态壳，只是"门面")
```

**FsUnionListenerBridge 何时使用？**

不是所有场景都需要 Bridge。判断标准：**三方 SDK 的回调监听器是在什么时机注册的？**

| 场景 | 监听器注册时机 | 是否需要 Bridge |
|---|---|---|
| 开屏广告 | `showSplash()` 阶段注册（如穿山甲 `setSplashAdListener`） | ❌ 不需要，直接用闭包 |
| 插件广告 | 广告对象构造时注册（如优量汇 `new UnifiedInterstitialAD(ctx, placeId, listener)`） | ✅ 需要 Bridge |
| 激励视频 | 广告对象构造时注册（如优量汇 `new RewardVideoAD(ctx, placeId, listener)`） | ✅ 需要 Bridge |
| 信息流模板 | 广告对象构造时注册 | ✅ 需要 Bridge |
| 信息流自渲染 | 广告对象构造时注册 | ✅ 需要 Bridge |

### 11.3 开屏广告 Adapter

**参考实现**: `PangleSplashAdapter.java`（无需 Bridge 的简单模式）

**继承类**: `FsCustomSplashAdapter`

**需实现的方法**: `getSdkType()`, `getSdkName()`, `getAdapterVersion()`, `initialize()`, `isInitialized()`, `request()`, `showSplash()`

```java
package com.example.adapter;

import android.content.Context;
import android.view.ViewGroup;
import com.ima.union.adapters.custom.FsCustomSplashAdapter;
import com.ima.union.core.adapter.AdCallback;
import com.ima.union.core.adapter.AdAdapterRegistry;
import com.ima.union.core.adapter.SplashAdListener;
import com.ima.union.core.model.*;
import com.ima.union.utils.FsLogger;

/**
 * 自定义开屏广告适配器。
 *
 * <p>开屏广告的展示监听器在 showSplash 阶段注册（而非广告对象构造时），
 * 通常不需要 FsUnionListenerBridge，直接在 showSplash 中使用闭包即可。</p>
 */
public class MyNetworkSplashAdapter extends FsCustomSplashAdapter {

    private static final AdSdkType SDK_TYPE = AdSdkType.of("MYNETWORK", "我的广告平台");
    private static final String TAG = "MyNetworkSplashAdapter";

    /**
     * 存储 init 时的 appId，供 isInitialized() 统一委托。
     * initAppId 是实例级字段但在 SDK 初始化时写入一次后不再变化，不会造成并发问题。
     * 如果采用 per-request 新建实例方案，此字段也不需要。
     */
    private String initAppId;

    @Override
    public AdSdkType getSdkType() { return SDK_TYPE; }

    @Override
    public String getSdkName() { return "我的广告平台"; }

    @Override
    public String getAdapterVersion() { return "mynetwork_1.0.0"; }

    @Override
    public boolean isInitialized() {
        return initAppId != null
                && AdAdapterRegistry.getInstance().isInited(getSdkType(), initAppId);
    }

    @Override
    public void initialize(Context context, String appId,
                           com.ima.union.core.adapter.AdInitCallback callback) {
        this.initAppId = appId;
        // 初始化三方广告 SDK
        try {
            MyNetworkSDK.init(context.getApplicationContext(), appId);
            callback.onInitSuccess();
        } catch (Exception e) {
            callback.onInitFailure(-1, "初始化失败: " + e.getMessage());
        }
    }

    @Override
    public void request(Context context, AdRequestParams params,
                        AdSourceConfig sourceConfig, AdCallback callback) {
        String sdkName = sourceConfig.getSdkName();
        try {
            // 加载广告，超时控制建议用 AdLoadTimeout
            com.ima.union.core.adapter.AdLoadTimeout timeoutCtrl =
                    new com.ima.union.core.adapter.AdLoadTimeout(
                            sourceConfig.getTimeout(), sdkName, callback);
            timeoutCtrl.start();

            MyNetworkSDK.loadSplashAd(sourceConfig.getAdUnitId(),
                    new MyNetworkSDK.LoadListener() {
                        @Override
                        public void onLoaded(Object nativeAd, double ecpm) {
                            timeoutCtrl.finish();
                            UnionAdResponse response = new UnionAdResponse.Builder()
                                    .sdkName(sdkName)
                                    .sdkType(getSdkType())
                                    .adUnitId(sourceConfig.getAdUnitId())
                                    .adFormat(AdFormat.SPLASH)
                                    .nativeAd(nativeAd)
                                    .ecpm(ecpm)
                                    .expireTimeMs(sourceConfig.getExpireTimeMs())
                                    .build();
                            if (callback != null) {
                                callback.onLoaded(response);
                            }
                        }

                        @Override
                        public void onFailed(int code, String msg) {
                            timeoutCtrl.finish();
                            if (callback != null) {
                                callback.onLoadFailed(FsAdErrorCode.SDK_LOAD_FAILED,
                                        FsAdErrorCode.buildMsg("SDK加载失败", sdkName, code, msg));
                            }
                        }
                    });
        } catch (Exception e) {
            if (callback != null) {
                callback.onLoadFailed(FsAdErrorCode.REQUEST_EXCEPTION,
                        FsAdErrorCode.buildMsg("请求异常", sdkName, 0, e.getMessage()));
            }
        }
    }

    @Override
    public void showSplash(Context context, UnionAdResponse response,
                           ViewGroup container, SplashAdListener listener) {
        // ===== 非空安全校验（必须） =====
        if (response == null) {
            FsLogger.e(TAG, "showSplash: response is null");
            if (listener != null) listener.onAdError(FsAdErrorCode.AD_OBJECT_INVALID,
                    FsAdErrorCode.buildMsg("广告对象无效"));
            return;
        }
        // ===== 广告对象非空校验 =====
        Object nativeAd = response.getNativeAd();
        if (nativeAd == null) {
            FsLogger.e(TAG, "showSplash: no ad object");
            if (listener != null) listener.onAdError(FsAdErrorCode.AD_OBJECT_INVALID,
                    FsAdErrorCode.buildMsg("广告对象无效"));
            return;
        }

        try {
            container.removeAllViews();
            // 设置展示监听器（开屏可在 show 阶段直接注册，无需 Bridge）
            MyNetworkSDK.SplashAd splashAd = (MyNetworkSDK.SplashAd) nativeAd;
            splashAd.setListener(new MyNetworkSDK.SplashListener() {
                @Override public void onAdShow() {
                    if (listener != null) listener.onAdShow();
                }
                @Override public void onAdClick() {
                    if (listener != null) listener.onAdClick();
                }
                @Override public void onAdClose() {
                    if (listener != null) listener.onAdClose();
                }
                @Override public void onAdSkip() {
                    if (listener != null) listener.onSplashAdSkipped();
                }
            });
            splashAd.show(container);
        } catch (Exception e) {
            FsLogger.e(TAG, "showSplash exception: " + e.getMessage(), e);
            if (listener != null) listener.onAdError(FsAdErrorCode.SHOW_EXCEPTION,
                    FsAdErrorCode.buildMsg("展示异常"));
        }
    }
}
```

### 11.4 插屏广告 Adapter

**参考实现**: `GdtInterstitialAdapter.java`（使用 FsUnionListenerBridge 的典型示例）

**继承类**: `FsCustomInterstitialAdapter`

**需实现的方法**: `getSdkType()`, `getSdkName()`, `getAdapterVersion()`, `initialize()`, `isInitialized()`, `request()`, `showInterstitial()`

**关键模式**：如果三方 SDK 的插屏监听器在广告对象构造时就绑定（如 `new XxxInterstitialAd(ctx, placeId, listener)`），则需要用 `FsUnionListenerBridge` 桥接。

```java
package com.example.adapter;

import android.app.Activity;
import android.content.Context;
import com.ima.union.adapters.custom.FsCustomInterstitialAdapter;
import com.ima.union.core.adapter.*;
import com.ima.union.core.model.*;
import com.ima.union.utils.FsLogger;

import java.util.HashMap;
import java.util.Map;

public class MyNetworkInterstitialAdapter extends FsCustomInterstitialAdapter {

    private static final AdSdkType SDK_TYPE = AdSdkType.of("MYNETWORK", "我的广告平台");
    private static final String TAG = "MyNetworkInterstitialAdapter";
    private String initAppId;

    @Override public AdSdkType getSdkType() { return SDK_TYPE; }
    @Override public String getSdkName() { return "我的广告平台"; }
    @Override public String getAdapterVersion() { return "mynetwork_1.0.0"; }
    @Override public boolean isInitialized() {
        return initAppId != null && AdAdapterRegistry.getInstance().isInited(getSdkType(), initAppId);
    }
    @Override public void initialize(Context context, String appId, AdInitCallback callback) {
        this.initAppId = appId;
        MyNetworkSDK.init(context.getApplicationContext(), appId);
        callback.onInitSuccess();
    }

    @Override
    public void request(Context context, AdRequestParams params,
                        AdSourceConfig sourceConfig, AdCallback callback) {
        String sdkName = sourceConfig.getSdkName();
        try {
            AdLoadTimeout timeoutCtrl = new AdLoadTimeout(sourceConfig.getTimeout(), sdkName, callback);
            timeoutCtrl.start();

            // ▸ Bridge: 请求阶段注入 SDK 回调，展示阶段绑定 InterstitialAdListener
            FsUnionListenerBridge<InterstitialAdListener> showBridge = new FsUnionListenerBridge<>();

            // 注意：监听器在构造时就绑定
            XxxInterstitialAd ad = new XxxInterstitialAd(
                    context instanceof Activity ? (Activity) context : null,
                    sourceConfig.getAdUnitId(),
                    new XxxInterstitialAd.InterstitialListener() {
                        @Override
                        public void onAdLoaded(double ecpm) {
                            timeoutCtrl.finish();
                            Map<String, Object> extra = new HashMap<>();
                            extra.put(FsUnionListenerBridge.EXTRA_KEY, showBridge);

                            UnionAdResponse response = new UnionAdResponse.Builder()
                                    .sdkName(sdkName)
                                    .sdkType(getSdkType())
                                    .adUnitId(sourceConfig.getAdUnitId())
                                    .adFormat(AdFormat.INTERSTITIAL)
                                    .nativeAd(ad)
                                    .ecpm(ecpm)
                                    .extra(extra)  // ← 把 Bridge 放入 extra
                                    .expireTimeMs(sourceConfig.getExpireTimeMs())
                                    .build();
                            if (callback != null) callback.onLoaded(response);
                        }

                        @Override
                        public void onAdLoadFailed(int code, String msg) {
                            timeoutCtrl.finish();
                            if (callback != null)
                                callback.onLoadFailed(FsAdErrorCode.SDK_LOAD_FAILED,
                                        FsAdErrorCode.buildMsg("SDK加载失败", sdkName, code, msg));
                        }

                        // === 运行时回调：通过 Bridge 获取当前展示监听器 ===
                        @Override
                        public void onAdShow() {
                            InterstitialAdListener l = showBridge.get();
                            if (l != null) l.onAdShow();
                        }

                        @Override
                        public void onAdClick() {
                            InterstitialAdListener l = showBridge.get();
                            if (l != null) l.onAdClick();
```

### 11.8 注册与生效

适配器实现完成后，有**两种注册方式**（推荐方式一）：

#### 方式一：后台配置（推荐，零代码接入）

在后台 JSON 配置中为自定义 ADN 广告源添加 `adapterClassName` 字段：

```json
{
    "strategy": {
        "slotId": "10000006",
        "strategies": [{
            "type": "WATERFALL",
            "priority": 1,
            "timeoutMs": 3000,
            "sources": [{
                "sdkName": "我的广告平台",
                "sdkType": "MYNETWORK",
                "adUnitId": "your_ad_unit_id",
                "appid": "your_app_id",
                "adapterClassName": "com.example.adapter.MyNetworkSplashAdapter",
                "priority": 1,
                "bidFloor": 1.0,
                "timeout": 5000,
                "enabled": true
            }]
        }]
    }
}
```

**关键字段说明：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sdkName` | String | ✅ | 广告源全局别名，必须与 `getSdkName()` 返回值一致 |
| `sdkType` | String | ✅ | 自定义类型 key，与 `AdSdkType.of(key, name)` 中的 key 一致 |
| `adapterClassName` | String | ✅ | Adapter 全路径类名，聚合 SDK 首次解析时通过反射创建实例 |

**生效流程**：后台下发 JSON → `AdSourceConfig.fromJson()` 解析 `adapterClassName` → `StrategyUtils.resolveAdapter()` registry miss → `AdapterFactory.createIfAbsent()` **反射 `Class.forName()` 创建 + 注册** → 后续同 key 请求直接 registry 命中。

> ⚠️ **安全约束**：`Class.forName()` 只能加载 APK 内已打包的类，Android 不允许动态加载外部 dex，不存在远程代码注入风险。适配器类必须打包在 APK 内。

#### 方式二：代码注册

在 `FsUnionSDK.initialize()` 之后手动注册：

```java
FsUnionSDK.registerCustomAdapter(new MyNetworkSplashAdapter(), AdFormat.SPLASH);
FsUnionSDK.registerCustomAdapter(new MyNetworkInterstitialAdapter(), AdFormat.INTERSTITIAL);
```

此时后台 JSON **不需要**配置 `adapterClassName` 字段。

### 11.9 完整接入 Checklist

开发自定义 ADN 适配器时，请逐一检查以下清单：

| # | 检查项 | 说明 |
|---|---|---|
| 1 | 继承正确的抽象类 | 开屏 → `FsCustomSplashAdapter`，插屏 → `FsCustomInterstitialAdapter`，激励视频 → `FsCustomRewardedVideoAdapter`，信息流 → `FsCustomFeedAdapter` |
| 2 | `getSdkType()` 唯一 | 通过 `AdSdkType.of("MY_KEY", "显示名")` 创建，key 需全局唯一 |
| 3 | `getSdkName()` 一致 | 返回值必须与后台 JSON 中 `sdkName` 一致 |
| 4 | **无成员变量存状态** | 禁止 `private XxxListener mShowListener` 等 per-request 成员字段 |
| 5 | 需要桥接用 `FsUnionListenerBridge` | 凡三方 SDK 监听器在构造时绑定，一律用 Bridge 通过 `response.extra` 传递 |
| 6 | Bridge 存入 `response.extra` | `extra.put(FsUnionListenerBridge.EXTRA_KEY, bridge)` |
| 7 | Bridge 绑定时机 | show/render 阶段从 `response.extra` 取出 → `bridge.bind(listener)` |
| 8 | Bridge 清除时机 | `onAdClose()` / `onAdDismissed()` 中调 `bridge.clear()` |
| 9 | **非空安全校验** | `show*/render*/register*` 入口必须校验 `response == null` 和 `nativeAd == null` |
| 10 | 容器非空校验 | 开屏/信息流涉及 `container` 参数时校验 `containerView == null` |
| 11 | **Close Guard 防重复** | 如果 `onAdSkip()` + `onAdClose()` 都会触发，用 `AtomicBoolean closedGuard` CAS 抢令牌 |
| 12 | 后台配置 `adapterClassName` | 生产环境推荐方式一，客户端零代码接入 |
| 13 | 混淆 Keep | adapter 类需要 keep：`-keep class com.example.adapter.** { *; }` |
| 14 | compileOnly 依赖 | Adapter 模块应使用 `compileOnly` 引用三方 SDK，由 app 模块 `implementation` 提供

## 14. 错误码

聚合 SDK 所有错误统一通过 `onAdError(code, msg)`（展示阶段）或 `onLoadFailed(code, msg)` / `onNoFill(msg)`（加载阶段）回调。错误码定义在 `FsAdErrorCode` 中，分为三个层级：

| 层级 | 范围 | 回调途径 | 说明 |
|---|---|---|---|
| Manager / Strategy 层 | 1001-1999 | `onNoFill` / `onAdLoadError` | 配置缺失、适配器解析失败、无填充等 |
| 加载阶段 | 2001-2999 | `onLoadFailed` | SDK 未初始化、超时、返回错误等 |
| 展示阶段 | 3001-3999 | `onAdError` | 容器空、渲染失败、播放错误等 |

> **错误消息格式**：`{聚合层提示} | {sdkName}[{三方SDK原始code}] {三方SDK原始msg}`
>
> 示例：`SDK加载失败 | Pangle[40001] no ad`
>
> 当错误为聚合层内部错误（无三方 SDK 参与）时，msg 仅包含聚合层提示。

### 14.1 Manager / Strategy 层 (1001-1999)

| 错误码 | 常量 | 含义 | 常见原因 | 解决建议 |
|---|---|---|---|---|
| 1001 | `CONFIG_NULL` | 合并配置为空 | ① 云端配置和 `defaultStrategyJson` 均未提供有效配置；② JSON 格式错误导致解析失败 | 检查 `load()` 时是否传入了 `defaultStrategyJson`；确认 JSON 格式合法（可用在线 JSON 校验工具） |
| 1002 | `ADAPTER_RESOLVE_FAILED` | 适配器解析失败 | ① `sdkType` 配置了未内置且未注册自定义适配器的平台；② 平台 SDK 未引入依赖 | 确认 `sdkType` 值正确（`PANGLE` / `GDT` / `BAIDU` / `FISSION`）；自定义平台需调用 `FsUnionSDK.registerCustomAdapter()` 注册 |
| 1003 | `NO_FILL` | 所有广告源均无填充 | ① 所有平台的 Bid 均低于 `bidFloor` 或超时；② 广告位未审核通过或未放量；③ 网络异常导致全部 SDK 请求失败 | 检查各平台广告位状态；适当降低 `bidFloor`；增大 `timeoutMs`；确认网络连通 |
| 1004 | `SLOT_ID_MISMATCH` | slotId 校验不通过 | `AdRequestParams.slotId` 与 JSON 配置中的 `slotId` 不一致 | 确认请求参数的 slotId 与 JSON 配置完全一致（严格匹配，不 fallback） |

### 14.2 加载阶段 (2001-2999)

| 错误码 | 常量 | 含义 | 常见原因 | 解决建议 |
|---|---|---|---|---|
| 2001 | `SDK_NOT_INITIALIZED` | SDK 未初始化 | ① 未调用 `FsUnionSDK.initialize()`；② 初始化尚未完成就发起广告请求；③ 某平台 SDK 初始化失败 | 确保 `Application.onCreate()` 中调用初始化；在初始化回调 success 后再加载广告；检查各平台 appId 配置 |
| 2002 | `SDK_LOAD_TIMEOUT` | 适配器请求超时 | ① 三方 SDK 在 `timeout` 时间内未返回结果；② 网络环境差 | 适当增大 `AdSourceConfig.timeout`（默认 5000ms）；检查网络连通性 |
| 2003 | `SDK_LOAD_FAILED` | SDK 返回加载错误 | ① 广告位 ID 或 AppId 配置错误；② 广告位未审核通过；③ 设备频率限制；④ 三方 SDK 内部错误 | 查看 msg 中三方 SDK 原始错误码（如穿山甲 `40001` 表示无广告），对照各平台错误码文档排查 |
| 2004 | `SDK_NO_AD_RETURNED` | SDK 返回空列表 | 三方 SDK 加载回调成功但未返回广告对象 | 通常是三方 SDK 的临时异常，重试即可；持续出现需联系平台技术支持 |
| 2005 | `REQUEST_PARAM_INVALID` | 请求参数无效 | ① `slotId` 为空；② 必填的 `adUnitId` / `appId` 缺失；③ 参数格式非法 | 检查 JSON 配置中各广告源的 `adUnitId` 和 `appId` 是否填写 |
| 2006 | `REQUEST_EXCEPTION` | 请求过程抛出异常 | ① 三方 SDK 内部 bug；② 反射调用失败；③ 设备兼容性问题 | 查看 Logcat 中 `FsUnionSDK` 前缀的异常堆栈，定位具体异常类型 |
| 2007 | `ADAPTER_CREATE_FAILED` | SDK 客户端创建失败 | ① 穿山甲 `TTAdNative` 创建失败；② SDK 未正确初始化导致内部对象不可用 | 确认 SDK 已初始化且 `appId` 正确；重启 App 重试 |

### 14.3 展示阶段 (3001-3999)

| 错误码 | 常量 | 含义 | 常见原因 | 解决建议 |
|---|---|---|---|---|
| 3001 | `ADAPTER_TYPE_MISMATCH` | 适配器类型不匹配 | 适配器未实现对应广告格式的接口（如用 Splash 适配器请求 Interstitial） | 检查 JSON 配置中广告格式与广告位是否匹配 |
| 3002 | `CONTAINER_NULL` | 展示容器为空 | 开屏广告 `show(container)` 时传入的 ViewGroup 为 null | 确保布局中容器 View 已初始化，在 `setContentView()` 之后调用 `show()` |
| 3003 | `AD_OBJECT_INVALID` | 广告对象无效 | ① 广告已过期被回收；② `response.getNativeAd()` 返回 null | 在 `show()` 前调用 `isReady()` 检查广告有效性；过期则重新加载 |
| 3004 | `SHOW_EXCEPTION` | 展示过程抛出异常 | ① Context 不是 Activity（激励视频/插屏需 Activity）；② 三方 SDK 内部异常 | 确保传入 Activity Context；查看 Logcat 异常堆栈定位 |
| 3005 | `RENDER_FAILED` | 渲染失败 | ① 信息流模板 ExpressView 创建失败；② 模板素材数据不完整 | 重试加载；持续出现需检查三方平台广告位配置 |
| 3006 | `PLAYBACK_ERROR` | 视频播放错误 | ① 视频素材下载失败；② 播放器内部错误；③ 设备不支持视频格式 | 检查网络环境；确认设备支持视频解码；联系平台排查 |
| 3007 | `SDK_SHOW_ERROR` | SDK 展示阶段错误 | 三方 SDK 在展示环节返回错误（如穿山甲 `onVideoError`、百度 `onVideoDownloadFailed`） | 查看 msg 中三方 SDK 原始错误信息，对照平台文档排查 |

### 14.4 错误排查流程

```
收到 onAdError / onLoadFailed / onNoFill
         │
         ▼
   查看 errorCode
         │
    ┌────┼─────────────────┐
    ▼    ▼                 ▼
1001-1999  2001-2999    3001-3999
 策略层     加载层         展示层
    │         │              │
    ▼         ▼              ▼
 配置/   SDK初始化/     容器/对象/
 适配器   网络/超时      渲染/播放
 问题    /参数问题       问题
    │         │              │
    └────┬────┘──────────────┘
         ▼
  查看 msg 中的三方 SDK 原始错误码
  （格式：sdkName[原始code] 原始msg）
         │
         ▼
  对照各平台错误码文档进一步排查
```

> 💡 **排查技巧**：开启 `enableLog(true)` 后，所有错误日志统一输出在 `FsUnionSDK` 前缀下。通过 `logcat -s FsUnionSDK:*` 过滤可快速定位错误链路。

## 15. 常见问题

### Q1：SDK 未初始化就调用广告会怎样？

`FsUnionSDK` 会抛出 `IllegalStateException: FsUnionSDK is not initialized`，请确保在 `Application.onCreate()` 中先调用 `FsUnionSDK.initialize()`。

### Q2：所有广告源都加载失败了怎么处理？

策略引擎会回调 `onAdError()` 或（瀑布流/竞价均失败时）`onNoFill`。建议在 `onAdError` 中做降级处理，例如展示备用内容或直接跳过广告展示。

### Q3：超时时间设置多少合适？

`timeoutMs`（整个策略执行的最大超时时间）建议 2500-3000ms。该时间包含平台 SDK 初始化 + 各广告源请求召回。
- 太短：可能导致部分平台没有返回 Bid
- 太长：会影响用户体验
可通过 JSON 的 `timeoutMs` 字段配置。

### Q4：如何在运行时关闭某个广告源？

在 JSON 配置中，将该广告源的 `enabled` 设为 `false`，或在 `sources` 列表中移除该源。如需动态控制，可通过服务端下发 JSON 配置来动态调整。

### Q5：飞梭平台为什么要在初始化前配置 Token？

飞梭 SDK 的初始化机制需要在 `FissionSdk.init()` 被调用时就传入 Token，而聚合 SDK 的内部初始化流程在 `FsUnionSDK.initialize()` 内执行，因此需要在此之前预先注入。

### Q6：策略类型在哪里配置？

策略类型（`WATERFALL` / `BIDDING` / `HYBRID`）在 JSON 配置的 `strategyType` 字段中指定，通过 `load(defaultStrategyJson)` 传入，支持云端下发和热更新。

### Q7：为什么要在展示前调用 isReady()？

广告加载成功后（`onAdShow` / `onAdLoaded` 回调到达时），素材可能随缓存过期、设备状态变化等原因变为「未就绪」状态。例如百青藤自渲染广告的 `NativeResponse.isReady()` 会在广告过期后返回 `false`。

**务必在调用 `show()` 前检查：**

```java
@Override
public void onAdShow(IFsUnionSplashAd ad) {
    if (ad.isReady()) {
        ad.show(splashContainer);
    } else {
        // 广告已失效，放弃此次展示
        navigateToMain();
    }
}
```

- `isReady()` 是**实时检查**，每次调用都会重新查询，不是加载时的快照值
- 竞价比价时，`isReady() = false` 的广告不会参竞，避免浪费竞价名额
- 对于未提供就绪检查的 SDK（如穿山甲/优量汇/飞梭），`isReady()` 始终返回 `true`

### Q9：如何在运行时获取当前集成的 SDK 版本号？

通过 `FsUnionSDK.getVersion()` 或 `FsUnionSdkVersion.getVersion()` 获取语义化版本号（如 `1.0.0-java`），
通过 `getVersionCode()` 获取整型构建号。两个 API 都不要求 SDK 已初始化，适合在日志、埋点、自检等场景使用。

```java
String version = FsUnionSDK.getVersion();      // "1.0.0-java"
int code = FsUnionSDK.getVersionCode();        // 1
```
